# Migrating from 0.5.x to 0.6.0

This guide covers every breaking or action-required change between the 0.5.x
series and 0.6.0. 0.6.0 is a convergence release: dead crates were retired,
diagnostics moved to owning crates, the `copybook` facade was curated, and
three stable language features lost their runtime flags. The JSONL contract
is unchanged; CLI output, exit-code mapping, and `encode` strictness changed
as documented in section 7.

## 1. Retired crates (package moves)

Thirteen workspace crates from 0.5 were removed ahead of 0.6.0 and their
functionality folded into owning crates (a fourteenth, `copybook-record-io`,
remains as a compatibility forwarder — see pattern B). Two patterns apply —
check which one covers each dependency you hold:

**A. Internal helpers, no public successor.** These crates exposed
`pub` helpers that were only ever consumed inside the workspace. Their
logic now lives in `pub(crate)` internals (`copybook-core::internal`)
with no public re-export. If you depended on them directly, drop the
dependency; the behavior remains available through the normal
parse/decode paths and the CLI.

| 0.5 crate | Public API removed | Still available via |
| --- | --- | --- |
| `copybook-safe-ops`, `copybook-safe-index`, `copybook-safe-text` | `safe_divide`, `safe_slice_get`, `parse_usize`, `safe_parse_u16`, … | Checked arithmetic inside core/codec; use std + typed errors directly |
| `copybook-overflow` | `safe_u64_to_u32`, `safe_array_bound`, … | `TryFrom` conversions + `copybook::error` codes |
| `copybook-utils` | `OptionExt`, `VecExt`, `SliceExt` traits | `.ok_or_else` + typed errors directly |
| `copybook-corruption`, `copybook-corruption-detectors`, `copybook-corruption-predicates` | `detect_ebcdic_corruption`, `detect_packed_corruption`, … | `copybook audit --detect-anomalies` for record scanning |
| `copybook-corruption-rdw`, `copybook-rdw-predicates` | RDW corruption/predicate helpers | `copybook-rdw::diagnostics` (`detect_rdw_ascii_corruption`, `rdw_is_suspect_ascii_corruption`), or `copybook::framing::rdw` from the facade |

**B. Collapsed into a surviving crate with a new path.**

| 0.5 crate | 0.6 replacement | Notes |
| --- | --- | --- |
| `copybook-governance-contracts` | `copybook-governance` (`governance::feature_flags`, re-exporting `copybook-contracts`) | Single-crate surface since #656 Phase F |
| `copybook-governance-grid`, `copybook-governance-runtime` | `copybook-governance` (`governance::bindings`, `governance::runtime`) | Same split, one crate |
| `copybook-record-io` | `copybook-codec::file::dispatch` | The 0.5 crate name remains resolvable as a compatibility forwarder with no independent implementation; the facade path `copybook::record_io` is `#[deprecated]` |

`copybook-rdw` was **not** retired: it remains the live RDW framing crate
(`copybook::framing::rdw` is the preferred facade path).

The experimental `copybook-arrow` adapter is unchanged in
location but remains experimental: see section 5. (Kafka support lives in
`examples/kafka_pipeline` and `examples/kafka_streaming`, which are outside
the workspace.)

## 2. Facade curation (`copybook` crate)

The facade now re-exports the real crates as modules (`copybook::core`,
`copybook::codec`, `copybook::framing`, …) instead of maintaining parallel
copies. Eight legacy module aliases are `#[deprecated]` since 0.6.0. The
owning source removes them after the 0.6 migration window — i.e. no earlier
than 0.7.0; the removal will be announced under `Removed` in the
[CHANGELOG](../../CHANGELOG.md). (Post-1.0, the
[deprecation policy](../STABILITY_GUARANTEES.md) guarantees two minor
versions; pre-1.0 minors may carry breaking changes, which is why this
guide exists.):

| Deprecated path | Use instead |
| --- | --- |
| `copybook::codepage` | `copybook::charset` |
| `copybook::contracts` | `copybook::core::feature_flags` |
| `copybook::determinism` | `copybook::codec::determinism` |
| `copybook::error_reporter` | **removed from the facade in 0.6.0** (§4): depend on the `copybook-error-reporter` compat crate directly through the 0.6 window; new code uses `copybook::error` taxonomy types plus owning-crate diagnostics such as `copybook-rdw::diagnostics` |
| `copybook::fixed` | `copybook::framing::fixed` |
| `copybook::options` | `copybook::codec::options` |
| `copybook::overpunch` | `copybook::codec::numeric::overpunch` |
| `copybook::rdw` | `copybook::framing::rdw` |
| `copybook::record_io` | `copybook::codec::record` or `copybook::codec::file::dispatch` |

**Semver discipline.** A facade minor release can no longer silently carry
breaking changes from a granular crate; granular breaking changes now bump
the facade major. Pin `copybook` with `=` or `~` in lockstep-sensitive
builds (see [Stability guarantees](../STABILITY_GUARANTEES.md)).

**Which package to depend on.** `copybook` is the canonical dependency:

```toml
copybook = "0.6"
```

`copybook-rs` is a redirect/search alias for the same API — do not add it
alongside `copybook`. Depending on granular crates directly
(`copybook-core`, `copybook-codec`, …) remains supported but opts out of
the facade's lockstep guarantees; see
[Library API](../reference/LIBRARY_API.md) and the per-crate docs on
[docs.rs](https://docs.rs/copybook).

## 3. Feature flags removed (#656 Phase C)

SIGN SEPARATE, COMP-1, and COMP-2 were promoted to stable parser defaults in
0.4.3. In 0.6.0 their runtime flags were removed outright:

- `--enable-features` / `--disable-features` no longer accept `sign_separate`,
  `comp_1`, or `comp_2`; naming them is a hard `Invalid feature flag` error.
- `COPYBOOK_FF_SIGN_SEPARATE`, `COPYBOOK_FF_COMP_1`, and
  `COPYBOOK_FF_COMP_2` are ignored when set.
- No action is needed if you never set these: the behavior you got with the
  flags enabled is now the only behavior.

Current flag list: [Feature flags](../FEATURE_FLAGS.md). The remaining
runtime flags cover experimental (`renames_r4_r6`), enterprise, performance,
and debug/testing concerns only.

## 4. Diagnostics rehomed (#655)

Error reporting now lives with the layer that owns the error:

- `copybook-core` no longer re-exports `copybook-utils` or
  `copybook-error-reporter` (`copybook_core::{utils, error_reporter}` were
  compat shims with zero users; both are removed).
- `copybook::error_reporter` was removed from the facade in 0.6.0: a primary
  package cannot depend on a compat package, and reporting has no single
  primary owner. Depend on the `copybook-error-reporter` crate directly
  (still published through the 0.6 compatibility window):

  ```toml
  copybook-error-reporter = "0.6"
  ```
- RDW transfer diagnostics are owned by `copybook-rdw::diagnostics`
  (`detect_rdw_ascii_corruption`, `rdw_is_suspect_ascii_corruption`).
- The stable error-code taxonomy (CBKP/CBKS/CBKD/CBKE/CBKF/CBKR/CBKI
  families) and CLI exit codes (2=CBKD, 3=CBKE, 4=CBKF, 5=CBKI) are
  unchanged; only Rust import paths for the reporting helpers moved. See
  [Error codes](../reference/ERROR_CODES.md).

## 5. Experimental surfaces stay experimental

These APIs are published but explicitly excluded from stability guarantees
(they may change in any 0.6.x patch):

- `copybook-arrow` (Arrow/Parquet adapter)
- `renames_r4_r6` advanced scenarios (behind the `renames_r4_r6` flag;
  see [RENAMES_R4_R6](../RENAMES_R4_R6.md))

Do not gate a production migration on these paths. Everything else in the
facade follows the [stability guarantees](../STABILITY_GUARANTEES.md).

## 6. Behavior corrections (check your outputs)

The following 0.5 behaviors were bugs; 0.6.0 fixes them. If you pinned golden
files against 0.5 output, these are the diffs to expect:

- **REDEFINES decode** now reads from the redefined region start, not the
  group start. Records using REDEFINES decode differently (correctly).
- **OCCURS INDEXED BY with `format="ascii"`** no longer rejects already-ASCII
  COMP-X binary data.
- **Unknown `USAGE` clause** is a hard `CBKP001_SYNTAX` parse error
  (CLI exit 3) instead of silently defaulting to DISPLAY. A copybook that
  parsed with exit 0 in 0.5 now fails `copybook parse`.
- **COMP-3 regression**: `+0` encodes to `0x0C`, and `Ord` for
  `PackedDecimal` matches its `PartialEq`.
- **MSRV is 1.95** (raised from 1.92 in the 0.5 series). Toolchains older
  than 1.95 cannot build 0.6.0.

## 7. CLI behavior changes

Subcommands and the JSONL contract are unchanged, but output text, exit
codes, and `encode` strictness moved. Re-baseline scripts that parse stderr
or assert exit codes:

- **Exit codes corrected.** Unreadable files (copybook or input, all five
  commands) now exit 4 with the path and argument named, instead of 5 with
  a bare OS error. `encode` input-data failures now exit 3 (`CBKE`) instead
  of 5. `CBKR*` framing errors now exit 4 instead of 5.
- **`encode` is strict about unusable numbers.** A present-but-unusable JSON
  value for a zoned, packed, edited-numeric, or binary field no longer
  encodes as zeros with success; it raises `CBKE501_JSON_TYPE_MISMATCH`
  naming the field (absent fields and explicit `null` still keep defaults).
- **Failures are listed, not just counted.** `decode` and `encode` print
  each failed record's index and stable code on stderr. `encode --fail-fast`
  can actually be turned off now (`--no-fail-fast`).
- **Truncated inputs fail loudly.** A file that is not a multiple of LRECL
  raises `CBKR101_FIXED_RECORD_ERROR` (truncated RDW headers:
  `CBKF221_RDW_UNDERFLOW`) instead of `verify` reporting `PASS` on data
  `decode` refuses.
- **Human-readable output fixed.** `inspect` renders source PIC clauses,
  real binary widths, and level-88/LRECL/codepage values without Rust
  `Debug` formatting; `support` prints the `--check` IDs its footer
  references; `--help` describes the tool instead of flag internals.

## 8. Checklist

1. Replace retired crate dependencies and update `use` paths (§1).
2. Move facade imports off the nine deprecated aliases (§2).
3. Drop `sign_separate` / `comp_1` / `comp_2` from flag configs and env (§3).
4. Replace `copybook::error_reporter` with a direct
   `copybook-error-reporter` dependency, or move to owning-crate
   diagnostics (§4).
5. Re-baseline golden files if you use REDEFINES, INDEXED BY over ASCII
   COMP-X, or borderline USAGE/codepage inputs (§6).
6. Re-baseline scripts asserting CLI stderr text or exit codes (§7).
7. Build with Rust ≥ 1.95 (§6).
