# No-Panic Policy

## Goal

Production code and test code should be fallible, not panic-driven.
`copybook-rs` aims for zero unexpected panics in shipping code and zero
panic-family calls in tests that could be replaced by fallible helpers.

This does not ban `assert_eq!` in tests. Assertions remain valid test
oracles. The policy targets panic-family calls that substitute for proper
error handling: `unwrap`, `expect`, `panic!`, `todo!`, `unimplemented!`,
`unreachable!`, raw slice indexing, and unchecked arithmetic.

## Panic Families

| Family | Members |
|--------|---------|
| `unwrap` | `.unwrap()`, `.unwrap_or_else(|_| panic!(...))` |
| `expect` | `.expect("...")` |
| `panic_macro` | `panic!(...)` directly |
| `todo` | `todo!()`, `todo!("...")` |
| `unimplemented` | `unimplemented!()` |
| `unreachable` | `unreachable!()`, `unreachable!("...")` |
| `indexing` | `slice[n]`, `map[k]` with no bounds check |
| `string_slice` | `&s[n..m]` on a `String` or `str` |
| `get_unwrap` | `.get(n).unwrap()` pattern |
| `unchecked_time_subtraction` | `SystemTime::now() - duration` without checked sub |

`assert_eq!`, `assert!`, and `assert_ne!` are **not** in scope for phase 1.
They remain valid test oracles.

## Allowlist Schema

Allowlist entries are stored in `policy/no-panic-allowlist.toml`.

```toml
schema_version = "0.3"

[[allow]]
id = "panic-XXXX"
path = "crates/copybook-X/src/Y.rs"
family = "unwrap"
classification = "test_helper"
owner = "team/owner"
explanation = "Why the panic-family call is acceptable here."
expires = "YYYY-MM-DD"  # Required; max 90 days from creation

[allow.selector]
kind = "method_call"
container = "function_name_where_call_lives"
callee = "unwrap"
receiver_fingerprint = "std::fs::read_to_string(path)"

[allow.last_seen]
line = 42
column = 17
```

### Classification Values

| Classification | Meaning |
|----------------|---------|
| `test_helper` | Test fixture setup; migrate to fallible builder |
| `generated_code` | Generated by `copybook-gen`; fix at generation site |
| `infallible_by_invariant` | Logically impossible to fail; document the invariant |
| `temporary_debt` | Known tech debt; must carry expiry ≤ 90 days |
| `suppression_upstream` | Upstream crate constraint; link the issue |

### Selector Fields

| Field | Purpose |
|-------|---------|
| `kind` | `method_call`, `macro_call`, `index_expr`, `range_slice` |
| `container` | Function or method name where the call lives |
| `callee` | Method or macro name being called |
| `receiver_fingerprint` | Type expression of the receiver (advisory; not enforced structurally) |

### `last_seen` Fields

`last_seen` is advisory only. Line/column drift does not invalidate the entry.
The `xtask check-no-panic-family` command reports drift but does not fail
on it unless the call site is no longer present.

## Commands

After PR 02:

```bash
# Audit all panic-family calls and output JSON
cargo run -p xtask -- audit-unwraps --json

# Check against the allowlist (advisory initially)
cargo run -p xtask -- check-no-panic-family

# Propose new allowlist entries for current debt
cargo run -p xtask -- no-panic propose

# Full policy report including panic-family status
cargo run -p xtask -- policy-report
```

## Enforcement Phasing

| Phase | State | Condition |
|-------|-------|-----------|
| 1 — Visibility | Audit only; no CI gate | PR 02 merged |
| 2 — Advisory | `check-no-panic-family` in CI; non-blocking | PR 06 merged |
| 3 — Warn gate | New unallowlisted calls warn in CI | After PR 09 |
| 4 — Hard gate | Unallowlisted production panics fail CI | After allowlist is stable |

Do not enter Phase 4 before the allowlist has been stable (no new entries,
no expired entries) for ≥2 weeks.

## Relationship to Clippy

The no-panic allowlist and Clippy lint enforcement are complementary:

- Clippy `unwrap_used = "deny"` catches calls at compile time.
- The allowlist covers cases where Clippy suppression is genuinely needed.
- Every `#[expect(clippy::unwrap_used, ...)]` in the codebase must have a
  corresponding allowlist entry with an expiry date.

The allowlist schema is the audit trail. The `#[expect(...)]` attribute is
the source-level gate. Both must be present for any exception.

## xtask `no-panic propose`

`cargo run -p xtask -- no-panic propose` scans the workspace and emits a
candidate TOML block for each unallowlisted panic-family call.

The output is a starting point, not a final allowlist. Each entry must be:

1. Reviewed by a human.
2. Assigned an owner.
3. Given an expiry date ≤ 90 days from creation.
4. Classified correctly.
5. Committed to `policy/no-panic-allowlist.toml`.
