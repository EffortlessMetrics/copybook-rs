# Migrating from 0.8.0 to 0.8.1

This guide covers the byte-output corrections in 0.8.1. The public API, CLI
commands, exit codes, JSONL contract, and report formats are unchanged; only
the decoded characters and encoded bytes for six codepage slots change
([#998](https://github.com/EffortlessMetrics/copybook-rs/issues/998),
[#999](https://github.com/EffortlessMetrics/copybook-rs/issues/999)).

Related references:

- [CHANGELOG](../../CHANGELOG.md) (0.8.1 section — full entry list)

## 1. CP1140 Euro moves from 0xFF to 0x9F

Releases through 0.8.0 decoded CP1140 byte `0x9F` as `¤` (U+00A4) and byte
`0xFF` as `€` (U+20AC). Per IBM CP1140, `0x9F` is `€` and `0xFF` is the
control character U+009F. 0.8.1 corrects both directions:

| Operation | 0.8.0 (wrong) | 0.8.1 (correct) |
| --- | --- | --- |
| Decode `0x9F` | `¤` | `€` |
| Decode `0xFF` | `€` | U+009F |
| Encode `€` | `0xFF` | `0x9F` |
| Encode `¤` | `0x9F` | rejected (`CBKC301_INVALID_EBCDIC_BYTE`) |

CP037 is unchanged: `0x9F` remains `¤` there.

## 2. CP273 `~`/`ß` and CP1047 `^`/`¬` swaps corrected

| Codepage | Bytes | 0.8.0 (wrong) | 0.8.1 (correct) |
| --- | --- | --- | --- |
| CP273 | `0x59`, `0xA1` | `ß`, `~` | `~`, `ß` |
| CP1047 | `0x5F`, `0xB0` | `¬`, `^` | `^`, `¬` |

## 3. What to do about data produced with 0.8.0

Existing records converted with the wrong tables may be ambiguous: a `€`
decoded from `0xFF` under CP1140, or a `~` decoded from `0xA1` under CP273,
cannot be mechanically distinguished from legitimately correct data. 0.8.1
does not rewrite user records and does not guess legacy encodings. If your
pipeline stored conversion output (rather than the original EBCDIC bytes),
re-run the conversion from the original bytes with 0.8.1; if only converted
output survives, audit the six affected characters manually.
